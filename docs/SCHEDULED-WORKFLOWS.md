# 定时工作、资讯订阅与手机通知

MioBot 0.8.0 可把一件已确认的工作安排到稍后、每天或每周执行。后台到点再调用模型和只读资料工具，保存结果并尝试投递；电脑与手机查看同一实例的安排和收件箱。

本机可用，不需要先购买云服务器。本机模式需要电脑、MioBot 与托管引擎持续运行；完整云端模式需要云端 MioBot 服务持续运行，手机连接可达的云端地址。只把模型引擎放到远程机器，不等于完整后台已经搬到云端。

## 准备模型与搜索

先按 [README](../README.md) 安装固定版本引擎，在电脑配置自己的模型连接并测试。普通聊天成功与搜索可用是两项检查：需要联网的任务还要配置官方 DeepSeek 搜索或 Tavily。搜索、模型摘要和其他按需服务可能收费，使用自己的凭据和额度。

RSS 解析本身不需要额外模型或搜索服务，但生成摘要仍使用所选助手的模型。没有新条目时不调用模型。

## 创建一项定时工作

1. 在电脑或手机进入「安排」，选择助手，点「定时帮你办事 → 新建安排」。
2. 填写名称与具体要求，例如「搜索三条 AI 产品新闻，给出简短摘要与来源链接」。类型选择「交给助手处理」。
3. 选择只执行一次、每天或每周，并明确时刻；每周任务还要选择星期。当前统一使用北京时间 `Asia/Shanghai`。
4. 选择应用内聊天与收件箱，或当前助手已验证、支持主动发送且已绑定接收对象的渠道。
5. 核对内容、时间、接收位置和费用提示，再点「确认创建安排」。

也可在正常聊天里明确说「每天早上八点搜索三条 AI 新闻并整理来源」。模型提出计划后，程序按真实用户消息核对时间并调用任务工具；口头答应不等于任务已保存。模糊时间、多日复合表达等超出当前有限语法时，需要补充信息或用表单创建。

保存后还应核对「定时后台就绪」与下次执行时间。引擎未运行或挂接失败时，界面保留计划并显示原因，不会宣称已可按时执行。

## 添加公开订阅来源

1. 在同一助手的「安排 → 订阅来源」填写名称与公开 HTTPS RSS / Atom 地址，保存来源。
2. 新建安排，类型选「整理订阅资讯」，勾选该助手的来源。
3. 说明主题和输出方式，再选择频率、时间与接收位置并确认。

每位助手最多保存 20 个来源。保存只验证公开地址配置，不代表订阅内容已读通；首次执行时才抓取并检查 XML。当前不接受带访问令牌或账号密码的私人来源，也不接受本机、内网地址、HTTP 降级或任意重定向。抓取和来源链接都受公开 HTTPS 范围检查。

服务只解析文本 RSS / Atom，不安装 RSSHub 路由服务，不自动发现网站订阅、不抓取视频或媒体。若某网站只有普通网页，需要先找到公开订阅地址。本项目保留并实际调用 RSSHub 2.1.4 的原始 XML 解析模块；来源、哈希与许可证见 [集成说明](../integrations/rsshub/NOTICE.md)。

每个来源最多读取 2 MiB UTF-8 XML，拒绝 DTD、实体与过深文档。任务只把有限条目和最多 20,000 字符文本作为不可信资料交给模型，不将其中的角色、工具或执行指令当作用户授权。摘要保留原文链接。

## 查看、暂停与重试

每项安排保留执行记录，包括开始时间、结果、来源、错误与投递状态。暂停或取消会阻止未完成的排队工作；正在生成的任务会收到中止信号，晚到的结果不会继续发送。手动「现在执行一次」需要再次确认，可能产生 API 费用，不改变原周期。

生成暂时失败最多自动重试一次，间隔约 30 秒。相同助手的后续工作不会在前一个等待重试时越过，避免旧 RSS 快照稍后重复投递。已有生成结果在投递重试时复用，不重复向模型提问。

RSS 无新条目时保留已检查记录并跳过模型，也不推送空简报。部分来源失败与全部来源失败分别保留；全部失败不会伪装成「今天没有新闻」。确定没有投递的终态执行可清理待处理快照，已投递去重记录不受影响。

| 状态 | 实际含义 |
| --- | --- |
| 安排已保存 | 计划已持久化，还需原生定时后台确认绑定 |
| 已生成结果 | 模型或程序产生内容，尚不代表已投递 |
| 应用收件箱 | 结果已写入当前后台，可重新打开页面查看 |
| 外部服务已接受 | 渠道接口确认接收，不代表对方设备显示或已读 |
| 送达结果不确定 | 无法确认时先核对接收端，不自动重发 |
| 推送服务已接受 | 浏览器推送服务接受请求，不代表手机已显示 |

新定时工作由原生 CronJobManager 提供时钟与持久触发，MioBot 自有服务持有执行队列、只读工具边界和投递状态。RSS 抓取本身不会标为已发送；应用收件箱、执行完成与去重确认一起保存。任务执行阶段不获得再次排程、直接发送、通用终端或浏览器操作权限。

原有一次性文字提醒继续保留兼容入口。新定时工作可到点搜索或生成摘要，两者在「安排」页分别显示。

## 开启手机 Web Push

手机设置页提供通知连接入口，默认不弹权限请求。先连接手机能直接访问的 HTTPS 后台并配对；iPhone 用 Safari 添加到主屏幕，从图标打开后点「允许通知并连接」。保存后发送测试通知，亲自检查通知中心或锁屏。完整步骤见 [连接手机](MOBILE.md)。

普通局域网 HTTP 可以聊天和查收件箱，本实现不在该地址启用系统推送。关闭当前设备通知不取消任务；注销或撤销设备授权后，后台停止使用其订阅。推送只含简短提示和通知编号，正文保存在后台。Service Worker 不缓存个人 API 数据，也不提供离线模型执行。

当前已实现标准 Web Push 与 PWA 入口，未做原生 iOS / Android App；不应把通知用作保证响铃的闹钟。

## 当前验证边界

2026-11-05 的隔离验证包括：

- 真实固定原生引擎、CronJobManager 与临时 SQLite：一次性任务关闭并新建管理器后恢复同一任务 ID、重挂回调，实际等待定时触发并向本机 HTTP 接收器提交一次；另检查 daily 回调、周日映射、暂停与错过任务不重放。
- 原始 RSSHub 解析器：RSS / Atom、HTML 摘要清理、空订阅、DTD / 实体拒绝和长度限制；Node 服务使用临时来源与响应验证去重和投递后确认。
- 完整本机链路：正常原生模型工具创建 daily 工作、原生 Agent 经真实主工具桥读取本机替身搜索结果、原生一次性触发 RSS 解析及摘要、第二次无新条目时零模型请求。该记录完成 3 次后台执行；模型和搜索接口均为本机替身，付费调用与真实 QQ 发送均为 0。
- 服务与界面测试：请求幂等、取消、最多一次生成重试、重试期间保序、外部结果不明时不重发、RSS / 收件箱事务回滚、推送设备权限和替身服务接受状态。

这些检查证明特定功能链路和异常处理行为，不是模型智能、内容质量、性能提升、真实用户采用率或平台送达率评估。各检查含重复、边界和失败样本，自动化用例数不等于真实用户任务数。

真实 iPhone 的 HTTPS、主屏幕安装、通知授权与长时间锁屏送达仍待验收；Linux Docker 公网部署、真实 QQ 等渠道送达、连续运行负载和月度成本也没有新增验收结论。本机测试产物在忽略提交的 `artifacts/workflows-integration-20261105/`、`artifacts/rsshub-integration-20261105/`，不随公开源码分发。
