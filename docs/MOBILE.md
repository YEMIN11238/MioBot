# 用手机连接 MioBot

MioBot 0.6.1 提供手机网页版。电脑和手机连接同一个后台时，使用同一份助手、聊天、记忆和安排。手机不需要另外填写模型 API Key，也不会新建另一套机器人。

当前没有原生 iOS / Android App。手机系统推送尚未接通，提醒先保存在聊天和收件箱；请不要把收件箱出现一条记录当作锁屏通知已送达。

## 连接家里的电脑

1. 在电脑运行 MioBot，并完成模型与助手配置。让电脑和手机连接同一 Wi-Fi。
2. 打开电脑端「设置 → 运行位置 → 连接手机」。
3. 在「同一 Wi-Fi 访问」点击「允许连接」。这会开启独立的局域网端口 `4319`；本机桌面端继续使用自己的连接。
4. 检查显示的手机访问地址。多块网卡可能提供多个地址，选择手机能访问的 Wi-Fi 地址。
5. 点击「生成手机配对码」。配对码 5 分钟有效，只能使用一次。
6. 用手机的系统相机扫描二维码，打开页面；也可以手动打开电脑显示的地址，再输入配对码。
7. 核对将连接的后台名称，给手机设置容易辨认的设备名称，再确认连接。

小屏会自动进入手机界面；也可以在地址后添加 `?mobile=1`。二维码已经带有手机入口和本次配对信息，成功配对后会从页面地址清除配对信息。

电脑和后台需要保持运行。退出 MioBot、电脑关机或休眠后，手机就无法继续使用这台电脑的后台；仅隐藏桌面窗口不等于退出应用。

## 连接云端后台

先按 [云端部署指南](../README-cloud.md)准备完整 MioBot 服务，并在电脑「运行位置」中连接该云端实例。然后在同一页面的「连接手机」中生成配对码。

云端模式的二维码直接指向云端地址，手机不会通过当前电脑转发。云端服务保持运行时，关闭电脑不影响手机连接。

手机必须能直接访问云端 HTTPS 地址。`localhost`、`127.0.0.1` 指向打开链接的设备自身；电脑通过 SSH 本地端口转发访问的地址也不能直接交给手机。此时电脑端会提示地址不可用，需要先改为手机可达的云端地址。

切换到云端只切换到该实例自己的资料，不会自动上传或合并电脑上的助手、记忆、聊天、附件或密钥。多个设备连接同一实例，与多个不同实例之间的数据同步是两件事。

## 手机里可以做什么

底部保留四个入口：

- **聊天**：切换已启用助手、打开历史对话、发送消息、停止回复和重试最后一次失败回复。网页来源可点击查看。
- **安排**：查看当前助手的今日及后续一次性提醒，添加草稿并确认，修改时间、暂停、恢复或取消。时间按北京时间处理。
- **记忆**：查看、添加、编辑或删除当前助手的基础资料；只有主动勾选共享，才交给其他助手使用。
- **设置**：查看连接的后台与当前设备、打开收件箱、编辑助手名称和人设、断开这部设备。

手机设备权限限于个人使用。模型 API Key、后台启动部署、网络共享和其他设备授权管理继续在电脑端完成。设备配对不会自动合并不同 QQ 等消息平台的用户身份。

## 锁屏、断网与回复恢复

后台已接受的回复由后台继续执行。关闭网页、锁屏或切换网络只中断观看连接；重新打开页面会核对后台状态并读取已有回复。明确点击「停止回复」才请求取消。

如果消息提交后没有收到确认，页面会保留原请求编号，并提供「核对结果」「重试原消息」。先核对可以避免不必要的重复操作；明确重试时沿用原编号，后台按编号去重。连接恢复本身不会自动重发聊天或创建提醒。

这个机制不保证后台进程关闭后仍能继续生成。后台退出、重启或模型失败仍会中断该轮回复；重新连接与模型执行断点续跑不是同一能力。

草稿与待确认请求只属于原后台，不能切换后台后直接重发。后到的发送确认不会清除之后的新草稿。断开设备会清除当前页面的草稿、待确认请求与视图缓存，后台资料保留。

## 断开设备与关闭共享

电脑端「连接手机 → 已连接设备」列出设备名称和最近使用时间。点击「断开」后，该设备需要重新配对。手机也可以在「设置」中断开自身。

如果不再使用本地手机访问，在电脑端关闭「同一 Wi-Fi 访问」即可停止局域网监听；这不会删除聊天、记忆和任务。之后再次开启时，仍需有效的设备授权。

配对不会把后台最高权限管理密钥交给手机。设备会话放在 HttpOnly Cookie 中，后台持久化其哈希与撤销状态，当前会话有效期为 30 天。配对码和二维码只交给自己的设备，不需要发到聊天或 Issue。

## 常见情况

| 现象 | 需要核对 |
| --- | --- |
| 手机打不开地址 | 电脑与手机是否同一 Wi-Fi，是否允许连接、电脑仍在运行、所选地址是否对应当前网络；访客 Wi-Fi 可能隔离设备。 |
| 显示配对码无效 | 配对码可能已使用或超过 5 分钟，请在电脑重新生成。连续失败过多时需要稍后再试。 |
| 提示后台实例不一致 | 不要继续使用旧二维码，检查手机打开的地址，并从目标后台重新生成链接。 |
| 页面显示离线旧记录 | 后台或网络暂时不可达；点击重连，核对更新后的任务状态，旧页面不能证明后台已完成任务。 |
| 手机锁屏没有弹提醒 | 当前系统推送尚未接通，请打开 MioBot 的聊天或收件箱查看。 |
| 手机不能修改后台设置 | 个人设备权限不包含后台模型密钥、部署控制和其他设备授权，请回电脑管理。 |
| 输入时底部导航收起 | 键盘展开时优先显示聊天和输入框；点输入框旁的向下箭头收起键盘，导航会恢复，草稿保留。 |
| 旧页面弹键盘后整体上移 | 先将电脑后台更新到 0.6.1，再收起键盘并刷新手机网页。若仍出现，请记录手机系统与浏览器版本。 |

## 实现与验收范围

手机界面、设备授权和共享状态接入 MioBot 自有后台，AstrBot 继续负责原有模型、会话与工具循环。连接恢复实际适配 T3 Code 的小型重试函数及常量，原始片段、固定提交、MIT 许可与修改说明在 [T3 Code 集成记录](../integrations/t3code/NOTICE.md)。完整 T3 SDK、T3 Connect、官方手机 App 和推送服务未接入。

当前已通过隔离 HTTP 与替身模型测试，没有使用付费模型或现用账号。真实 iPhone 相机扫码、移动网络切换、长时间锁屏、原生系统推送和 Linux 公网生产部署仍需要分别实测。界面预览中的离线示例不构成这些项目的验收结论。
