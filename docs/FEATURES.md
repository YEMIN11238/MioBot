# 功能与边界

本页说明 MioBot 0.7.0 的实际行为，供配置、测试和反馈时参考。这里只列当前实现，不将路线图当作已交付功能。

## 助手、人设与会话

0.7.0 在「扩展 → 大肥鱼同款组件」加入9个可选QQ原生组件，默认不加载。它们随包提供，需要绑定已验证的主人私聊渠道后启用；来源、具体范围与验收边界见 [组件对照](CLOUD-PLUGIN-PARITY.md)。原生图库和Web媒体桥保持独立，同款组件不意味着电脑／手机网页自动支持所有QQ原生媒体行为。

每个助手有独立的人设、默认模型、能力配置和聊天。已有陪伴、游戏、求职预设，可自行编辑。修改人设或手动记忆会更新后续请求的上下文，保留会话前文。

表达增强使用已署名的插件，提供措辞规则、时间间隔和会话连续性等提示，并清理约定的内部标记。短回复完成清理后逐段显示；普通流式回复可逐字显示。停止和失败重试均有应用接口，重试不会新增同一条用户消息。

模型仍可能给出不合适或错误的回答。界面过滤思考通道、特定开头标记和已知包装格式，不保证能够识别任意模型自行写进正文的内部解释。人格提示也不意味着模型拥有真实情感或能自行执行所有事情。

## 基础记忆与增强记忆

### 基础记忆

- 明确的“记住……”指令保存原文事实，不自动从普通闲聊中抽取所有个人资料。
- 敏感凭据、执行指令、模糊引用和过长内容会被拒绝或要求重新表述。
- 默认按助手隔离，只有显式共享的条目才可能出现在其他助手上下文。
- 每个助手最多保存 200 条自动创建的基础资料，每条最多 1000 字；达到限制时提示整理。
- 每轮按关键词、称呼和近期顺序选择，最多 12 条、2400 字。没有向量检索，也不把整份历史重复带入每次回答。
- 支持查看、编辑、停用或删除；保存失败时不应声称已经记住。

### 可选增强记忆

LivingMemory 2.8.2 提供原生记忆写入与召回工具。当前集成要求独立配置支持 `text-embedding-3-small`、1536 维的连接，并指定用于摘要的聊天模型。配置聊天成功不等于向量接口可用。

记忆页按用户和助手 persona 检查范围，可列出和删除对应条目。已验证的样例包括写入、新会话召回、不同助手隔离与删除，不代表已经完成长期记忆质量或真实使用费用评估。

删除任一记忆条目，不会同步抹去聊天原文和既有备份。不同消息平台的账号也不会自动被识别为同一个人。

## 一次性提醒

以下输入用于体验现有流程，结果仍需检查任务页和真实接收端：

```text
两分钟后提醒我休息一下
明天早上七点叫我起床
取消刚才的提醒
```

时间识别使用确定性的有限语法，支持相对时间和明确时刻，不能理解所有自然语言。时区按 `Asia/Shanghai`；不明确的时间先追问，不自行猜测。重复提醒会被明确拒绝，不能悄悄当成一次性任务创建。

用户在聊天里明确指定时间和内容时可以直接创建；表单创建的任务是草稿，需要确认。待执行任务可暂停、取消，修改时间后重新确认。关闭期间错过的任务标为过期，不静默补发并声称准时完成。

本地收件箱写入、桌面系统通知、外部渠道接口接受和用户实际收到属于不同结果。外部发送要求渠道已验证、绑定当前助手和明确接收位置。接口成功不代表接收者已读。

当前定时器发送保存的提醒内容，不会到点重新搜索、调用模型完成调研并生成新报告。

## 网页与文件

搜索支持官方 DeepSeek 搜索和 Tavily。DeepSeek 使用已保存连接的凭据引用，Tavily 配置独立搜索凭据。没有合适搜索服务时显示待配置，不将聊天 API 可用等同于联网可用。

每次搜索返回有限数量的标题、来源地址、摘要和检索时间，供所选模型回答。默认不进一步打开或操作来源网页，不支持点击、登录、填表或抓取任意站点。来源链接经过公开地址检查，资料按不可信内容处理，不作为系统指令执行。

文件阅读是可选工具，支持 TXT、Markdown、PDF 和 DOCX，单文件最多 10 MB。按附件编号读取当前用户和助手的已上传内容，受文本提取长度限制；不支持扫描件 OCR、任意本机路径读取或保证复杂排版完全还原。

## 主动关心

主动关心只对陪伴场景按配置启用，默认关闭。用户可调整空闲间隔、免打扰时段和每日限制。没有回应过上一条关心时，不会持续发下一条。

用于生成问候的上下文有数量和长度限制，主动生成不授权模型调用任务、搜索或发送工具；最终投递由 MioBot 服务管理。普通提醒指令不会被自动当作允许长期主动联系。

目前有策略、原生插件和隔离链路测试；没有长期真实用户效果数据或当前版本真实 QQ 送达验收。

## 可选语音与私有图库

语音使用单独配置的合成服务，必须提供有效模型与音色。当前实现按用户明确请求触发，没有默认随机语音回复。服务可用性、音质和费用取决于提供商，API 返回成功也需核对音频能否实际播放。

私有图库支持上传、标签管理和当前助手范围内的图片发送。当前版本不提供自动从 B站抓图或从 QQ 收藏表情自动收集的通用流程。历史部署或其他机器上的插件行为不等同于此仓库当前功能。

## 游戏与求职预设

Minecraft 工具使用 Java Edition 1.21.8 的固定资料，提供指南读取、物品查询、合成配方与一层直接材料计算。资料有版本与来源，不连接玩家、服务器或背包；没有配方记录也不代表该物品无法获得，不覆盖所有游戏版本、熔炼、掉落和交易。

求职预设提供相应人设与通用已授权工具，不包含专门训练的面试模型、招聘平台自动投递、真实访谈数据库或经过业务评估的求职工作流。

多个预设是独立助手，没有实现任务分解、Agent 间委派或多 Agent 协作。

## 本地、远程引擎与完整云端

| 模式 | 调度在哪里 | 数据在哪里 | 客户端关闭后的行为 |
| --- | --- | --- | --- |
| 本机托管 | 本机 MioBot 服务 | 本机数据目录 | 隐藏窗口可保留后台；退出应用或设备不可用时不能持续执行 |
| 仅连接外部 AstrBot | 本机 MioBot 服务 | MioBot 本机状态与外部引擎各自数据 | 不会因模型引擎远程运行就让本机提醒继续 |
| 完整 MioBot 云端配对 | 云端 MioBot 服务 | 云端实例自己的数据目录 | 云端服务可继续运行；电脑本机通知不会凭空在关闭后弹出 |

配对完整云端会暂停本机待办并关闭本机主动关心，避免两边重复执行。切回本机不停止云端实例，也不自动恢复旧待办；数据没有自动上传或合并。

云端代理支持断线提示与重新连接入口。已做本机双服务测试与手机设备授权检查；真实 Linux 公网部署、手机系统推送、不同渠道的账号统一和长期连续体验还需要分别验收。

## 模型与渠道配置

服务商目录来自固定版本运行时及已加载适配器。连接预设只是字段和协议帮助；必须填写实际模型 ID，并分别执行读取列表和短请求测试。平台订阅不自动提供对应 API 权限。

消息渠道需要自己的账号、合法可用的网关、对应适配器和登录状态。QQ、Discord、Telegram 等不能仅凭配置表单就认定已接通；B站和抖音专用连接尚未接通。

当前外部私人消息的信任桥主要开放提醒相关工具；不承诺所有桌面工具已在每个外部渠道获得同等能力。原平台进入的记录在应用内用于查看，继续对话需在原渠道或新建应用内会话。


## 手机 Web 与设备连接

0.6.0 新增紫白配色的手机布局，底部为「聊天、安排、记忆、设置」。小屏自动使用手机页面，也可在地址中添加 `?mobile=1` 预览；桌面页面继续保留。

- 聊天支持切换已启用助手、历史对话、发送、停止、最后失败回复重试和来源链接。不会把模型名、思考通道或内部工具日志作为聊天内容显示。
- 安排支持按日期查看当前助手的一次性任务，创建草稿后确认，也可修改时间、暂停、恢复或取消。时间按北京时间显示和提交。
- 记忆支持按当前助手查看基础资料，新增、编辑、删除及显式共享。修改或删除不会抹去原聊天和既有备份。
- 设置可查看后台、当前设备、收件箱和通知状态，编辑当前助手名称与人设；模型密钥、后台部署和其他设备授权继续在电脑端管理。

### 配对与权限

电脑「设置 → 运行位置 → 连接手机」生成一次性配对码。配对码 5 分钟有效，二维码链接把配对信息放在 URL 片段中；手机核对后台实例后提交，成功后清除页面地址中的配对信息。设备获得独立、可撤销的 HttpOnly Cookie 会话，后台仅持久化令牌哈希，不把最高权限管理密钥交给手机。

本地手机授权只适用于原本机后台。电脑切换到云端后，旧本地授权不能代理访问云端；手机需要使用电脑重新生成的云端配对链接直接连接该实例，也可以退出原本地设备会话。

本机共享默认关闭，用户允许后开启独立局域网端口 `4319`，关闭后不再接受局域网访问。仅知道地址或添加应用请求头，不能取得个人资料。云端手机直接连接已配置的可达地址；电脑自己的 `localhost` / SSH 转发地址不能作为手机地址。

这里的个人设备授权允许使用同一实例内的助手、聊天、记忆、任务和收件箱，拒绝后台密钥、部署控制和其他设备授权管理。它服务于同一位所有者，不提供商业多租户、自动合并 QQ 身份或跨实例资料同步。

### 连接恢复与发送确认

客户端有一个共享连接恢复管理器，页面回到前台或网络变化时重新核对后台；离线状态保留原记录并标明不是最新状态。重连只读取结果，不自动重发聊天、创建提醒或执行其他写操作。

后台回复与页面观看分开。页面断开、锁屏或切换网络时，已接受的后台回复继续执行，重新连接后读取同一回复；明确点击停止才取消。后台本身退出、重启或模型失败仍会中断执行，不能把页面恢复等同于模型任务断点续跑。

尚未确认接收的消息保留原请求编号，用户明确重试时继续使用该编号；后台对同一请求去重。请求只属于原后台实例，不能切换后台后直接重发。迟到确认只清除原提交草稿，不覆盖之后的新输入；设备退出会清除该页面的草稿、待确认请求与视图缓存。

### 通知和验证范围

手机系统推送尚未接通，当前没有原生 iOS / Android App。提醒写入聊天与收件箱不等于锁屏通知已送达；网页打开时可查看新记录。

已完成隔离 HTTP、替身模型和连接恢复检查；真实 iPhone 相机扫码、移动网络切换、长时间锁屏及生产云环境仍需要设备实测。界面示例使用离线测试数据，不包含实际用户资料。

连接恢复适配 T3 Code 的 `retryDelayMs` 与相关常量，原始片段及 MIT 许可见 [集成记录](../integrations/t3code/NOTICE.md)。手机界面、配对接口和 MioBot 状态管理是本项目实现，没有安装完整 T3 SDK、T3 Connect 或官方手机 App。
