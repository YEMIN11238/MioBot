# 豆包整条语音的主人控制补丁

基于作者包 `astrbot_plugin_seed_audio_tts` v0.2.0，仅增加普通回复的发送偏好控制。保留原提供商、音频合成及唱歌插件接口；适配 AstrBot v4.29.3。

## 配置

在原版插件配置中显式填写 `owner_session`，例如 `渠道ID:FriendMessage:对方QQ号`。必须是完整的主人私聊会话 ID；留空、群聊 ID、其他平台或发送者不符时，插件不发送普通语音，也不接受控制。

`reply_mode` 在同一配置页查看和修改，支持 `text`（文字，默认）、`voice`（持续语音）、`auto`（使用提供商原概率）。聊天切换会写回该字段，重载后保留，不依赖模型记忆。

| 主人当前明确输入 | 效果 |
| --- | --- |
| 不要发语音、别发语音了、不要语音、只用文字、只打字、用文字就行 | 保存文字模式；关闭原生当前会话 TTS；本次确认也只发文字 |
| 发语音、发条语音、发个语音、给我发个语音、来个语音、发段语音、发个语音我听听、用语音说一句、这句用语音、这次用语音 | 本条回复最多生成一次语音，不改变保存模式或原生会话开关 |
| 以后都用语音、以后都发语音 | 保存持续语音模式并显式打开原生当前会话 TTS |
| 恢复自动语音、恢复自动、可以偶尔发语音、偶尔发语音 | 保存自动模式并显式打开原生当前会话 TTS，使用提供商概率 |

识别只读取当前消息直接包含的文字，不读取对话历史或引用中的文字。接受有限句尾语气词，以及“别发语音了，我现在不方便听”这类明确关闭加简短原因。“能不能别发语音”作为关闭请求处理；“你会发语音吗”“为什么不发语音”“语音怎么收费”等能力、原因和费用问题不会改开关。引用中的内容、转发、代码块和多重意图不会被当作开关；在 QQ 引用回复时，只识别主人本次直接输入的文字，不读取引用内的消息。

原生工具 `set_voice_reply_mode` 使用同一主人、当前直接指令及事件校验，只返回真实执行状态；模型不能凭历史或猜测越过开关。复杂表达未识别时会拒绝切换，可使用上表明确指令，不承诺任意自然语言都能识别。

原版会话 TTS 开关仍可禁止自动和持续语音。后台改模式不会擅自重新打开这个开关；要开启，可在原版会话设置中打开，或使用明确的持续/自动指令。本次语音是主人对单条回复的显式授权，可以在文字模式下使用。

## 语音状态说明

语音提供商是否已加载、保存的文字/语音偏好、本条消息有没有获得单次语音授权分别向模型报告。“你现在可以发语音吗”这类能力问句保持当前偏好；已加载提供商时应说明功能已配置、默认用文字，不能把文字模式或会话暂停误说成后台未配置。原生分段 TTS 总开关关闭是整条语音插件的正常配置，用于避免重复合成。本状态说明只确认已加载的配置，实际生成和送达仍以合成和 QQ 结果为准。

## 兼容与部署

1. 通过原版插件上传更新本插件，预置插件配置的 `owner_session` 和 `reply_mode=text`。
2. 通过原版提供商更新接口保持 `enable=true`、`seed_audio_whole_reply=true`、`seed_audio_reply_probability=0.33`（或用户原先选择的概率）。提供商参数在实例初始化时缓存，修改这些参数后应通过原版接口保存以重载提供商。普通插件配置保存引起的热重载可继续复用现有 Seed 提供商，不要求额外操作。
3. 原生 `provider_tts_settings.enable` 保持 false；主人会话 `tts_enabled` 初始保持 false。初始化文字模式也会关闭此会话开关。
4. 本补丁不修改模型 Key、电脑操作权限、人设或其他插件。唱歌继续由独立插件处理，不会被普通语音开关拦截。

停止指令先递增本地取消序号，再保存设置；音频合成返回后会再次检查取消序号和会话开关。因此“关掉后又打开”不会让旧的在途普通语音重新发送。卸载或热重载时，旧实例也会停止交付。在途请求可能已经产生合成费用；补丁阻止其发送，无法撤回已送达的语音。

一次语音以当前事件的处理标记消费，分段处理或重复回调不会重复合成。合成失败时沿用原作者的文字回退，不自动重复调用语音服务。

## 控制审计

仅识别到主人的明确控制消息及合成失败、在途取消等异常路径，输出 `[SeedAudioControl]` INFO 结构化日志，字段为 `command`、`mode`、`once`、`native_gate`、`provider_loaded`、`decision`、`reason`、顶层组件类型 `component_types` 和直接文字组件数量 `direct_plain_count`。审计不包含聊天正文、用户账号、密钥、音频内容或路径；普通聊天未触发控制且无异常时不输出此审计。`record_ready` 表示音频消息已交给后续发送流程，不代表 QQ 已送达。

## 离线验证

在此 staging 的上级目录执行 `python3 -m unittest discover -s tests -v`。测试使用假 AstrBot 事件、配置和合成器，不联网，不读取用户凭据，也不发送 QQ 消息。
